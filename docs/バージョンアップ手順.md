# バージョンアップ手順

このテンプレートから作った自分のリポジトリ（設定を作るフォルダー）を、新しい計算式プラグインや新しい tools に合わせる手順です。**フォルダーを作り直す必要はありません。** 自分の設定（`settings/` など）と `.env` はそのまま使えます。

## 1. 何を更新するか

| 更新するもの | 場所 | いつ |
| :--- | :--- | :--- |
| 計算式プラグインの zip | `.env` の `FORMULA_PLUGIN_ZIP` | アプリの計算式プラグインを新しい版にしたとき（2 章） |
| tools（`@rex0220/formula-authoring-tools`） | `package.json`、`node_modules/` | tools が新しい zip に対応していないと出たとき、新しい tools の直しや機能を使いたいとき（3 章） |
| テンプレートの文書と設定（`CLAUDE.md`、`docs/`、`.claude/settings.json` など） | テンプレートのファイル | tools と一緒に（3 章） |

今の版は、ターミナルで次のコマンドで確かめます。

```
npx @rex0220/formula-authoring-tools version
```

1 行目に tools の版、2 行目に tools が扱う計算式プラグインの版（Ver.101 以降）と authoring API の版、その後に `.env` の zip の計算式プラグインの版が出ます。公開されている tools の最新の版は `npm view @rex0220/formula-authoring-tools version` で分かります。

## 2. 計算式プラグインを新しい版にしたとき

1. アプリに入れたものと同じ版の zip（配布元から入手したもの）を手元に置きます
2. `.env` の `FORMULA_PLUGIN_ZIP` を、その zip の場所に書き換えます（`.env` は自分で直します。AI は `.env` を読み書きできません）
3. `npx @rex0220/formula-authoring-tools version` で、zip の版と authoring API の版が出れば終わりです

- 計算式プラグインの版を上げても、tools の対応する authoring API の版のままなら tools を上げずに使えます（tools は zip のプラグイン ID で計算式プラグインの zip かを確かめます）
- 前の版の計算式プラグインで作った `settings/` の設定は、そのまま `normalize` / `calc` に使えます。`normalize` は書き出す設定の `PluginVersion` を zip の版にします
- 「計算式プラグインの版 … には対応していない」「authoring API の版 … には対応していない」と出たら、3 章で tools を上げます

## 3. tools とテンプレートを上げる

### 3.1 テンプレートのファイルだけを置き換える（おすすめ）

始める前に:

- 作業中の設定をコミットしておきます（`git status` で確かめる）
- テンプレートのファイル（`CLAUDE.md`、`README.md`、`.claude/settings.json` など）を自分で直していた場合、その変更は消えます。Claude Code の許可を足すなら `.claude/settings.local.json`、git で無視するファイルを足すなら `.git/info/exclude` に書いておきます

VSCode のターミナル（PowerShell でもコマンドプロンプトでも同じ）で:

```
git remote add template https://github.com/rex0220/formula-authoring.git
git fetch template
git checkout template/main -- .claude .mcp.json .env.example .gitignore CLAUDE.md README.md LICENSE kintone-connections.example.json package.json package-lock.json docs samples settings/README.md requirements/example.md policy/README.md
npm ci
npx @rex0220/formula-authoring-tools version
git commit -m "テンプレートの更新を取り込む"
git push
```

- `git remote add` は初回だけです（2 回目からは「already exists」と出るので飛ばします）
- `git checkout` で置き換わるのは、テンプレートのファイルだけです。自分の `settings/` `requirements/` `fields/` `kintone/` `policy/authoring-policy.json` と `.env` `records/` `users/` は変わりません（作業フォルダーの外の接続のファイルも）
- `git checkout` が置き換えたファイルはコミットの対象に入っているので、`git add` は要りません
- 置き換えるファイルの一覧は、テンプレートの版で変わることがあります。最新の一覧は GitHub の README の「テンプレートの更新を取り込む」にあります。一覧のファイルがテンプレートに無いと `pathspec … did not match` と出て何も置き換わらないので、そのファイルを外して実行し直します
- テンプレートで消えたファイルは手元に残ります。気になれば消してください
- 最後に Claude Code のセッションを始め直します（新しい `CLAUDE.md` と許可の設定を読むため）
- `git merge template/main` では取り込まないでください。テンプレートから作ったリポジトリはテンプレートと履歴がつながっていないので、手を入れていないファイルまで衝突し、解き方によっては `policy/authoring-policy.json` の承認が消えます

### 3.2 Claude Code に頼む

3.1 のコマンドは Claude Code にも実行させられます。

```
docs/バージョンアップ手順.md の 3.1 のとおりに、テンプレートの更新を取り込んで
```

- git と npm のコマンドのたびに確認が出るので、内容を見て許可します
- `.env` の zip の入れ替え（2 章）は自分で行います

### 3.3 tools だけを急いで上げる

文書はそのままで、tools だけを上げます（`0.2.0` は上げたい版）。

```
npm install --save-exact @rex0220/formula-authoring-tools@0.2.0
npx @rex0220/formula-authoring-tools version
```

`package.json` と `package-lock.json` が変わるのでコミットします。文書（`CLAUDE.md` など）は古いままなので、後で 3.1 を行ってください（3.1 で `package.json` もテンプレートのものに置き換わります）。

### 3.4 フォルダーを作り直す（git の操作に慣れていないとき）

1. README の「セットアップ」の 1〜2 のとおりに、テンプレートから新しいリポジトリを作り（private）、`npm ci` します
2. 古いフォルダーから、次のものを新しいフォルダーへ写します
   - `settings/`（`README.md` 以外）、`requirements/`（`example.md` 以外）、`fields/`
   - `policy/authoring-policy.json`
   - `.env`（zip の場所を新しい版にするなら、2 章のとおり書き換える）
   - 使っていれば `kintone/`、`.claude/settings.local.json`（接続のファイルは作業フォルダーの外）
   - `records/` と `users/` は写さなくてかまいません（取り直せます）
3. `npx @rex0220/formula-authoring-tools version` で確かめ、新しいフォルダーで Claude Code を開きます

これまでの設定の変更の履歴（git）は、古いリポジトリに残ります。

## 4. つまずいたら

| 出たもの | すること |
| :--- | :--- |
| `計算式プラグインの版 … には対応していない` / `authoring API の版 … には対応していない` | tools を新しい版にします（3 章） |
| `計算式プラグインの zip ではない（プラグイン ID …）` | `.env` の `FORMULA_PLUGIN_ZIP` が計算式プラグインの zip か（別のプラグインの zip でないか）確かめます |
| `PluginVersion … が zip より新しい` | 新しい版の計算式プラグインで作った（ダウンロードした）設定を、古い zip で検査しています。`.env` の zip をアプリに入れた版にします |
| `environments.json は tools 2.0.0 から使わない` | print-craft-authoring の古い形のフォルダーです。接続のファイル（`kintone-connections.example.json` が見本）に移し、`environments.json` を消します |
| 手元の文書が古い | 3.1 で文書を新しくします |

## 5. Claude Code のプラグイン `formula` を使うとき（任意）

Claude Code のプラグイン `formula`（[formula MCP](https://github.com/rex0220/formula-authoring-mcp)）を入れると、AI は tools の CLI の代わりに、プラグインのツールで同じ作業をします（保存の前の検査、模擬の計算、kintone からの読み取り）。このフォルダーと、`settings/`・`kintone/` の置き場所はそのまま使えます。

- **入れる**: ターミナルの `claude` で `/plugin install formula --marketplace rex0220/formula-authoring-mcp`（Claude Code 2.1.275 以降。Node.js 20 以降）
- **設定**: `/plugin configure formula@rex0220-formula` で
  - 計算式プラグインの zip: 空なら、このフォルダーの `.env` の `FORMULA_PLUGIN_ZIP` を使います
  - kintone の接続のファイル: 絶対パス。プラグインは `.env` の 1 接続の形（`KINTONE_BASE_URL` など）を読まないので、kintone を使うには接続のファイル（`kintone-connections.example.json` が見本）が要ります
  - 計算式プラグインの作業フォルダー: 空のまま。初めてツールを使うときに確認が出て登録されます。登録の後は `/mcp` で formula を再接続します
- **更新**: `/plugin marketplace update rex0220-formula` のあと、`/plugin` の Installed から更新します（ターミナルなら `claude plugin update formula@rex0220-formula`）。自動の更新は既定で切れています（`/plugin` の Marketplaces で有効にできます）
- プラグインを入れたら、テンプレートも 3.1 で新しくします（古い `CLAUDE.md` は `settings/` に直接書くよう AI に指示しますが、プラグインのフックがそれを止めます）
- プラグインは中核を束ねているので、このフォルダーの tools（npm）とは別に版が上がります。計算式プラグインの zip は同じものを使います
- 使わないときは、`/plugin` の Installed で無効にします。AI は [docs/AI作業手順.md](AI作業手順.md) の CLI の手順に戻ります
